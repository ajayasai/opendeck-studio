# Compatibility

OpenDeck Studio 0.1.0-alpha.5 is an alpha with a deliberately limited native document model. PPTX import/export transforms supported objects into a new document. It is not a lossless round trip, and an imported file can lose appearance or behavior. Full PowerPoint feature parity remains unfinished.

Keep the original PPTX. Use OpenDeck's native JSON for backups of OpenDeck documents. Review import warnings and compare the exported result in the presentation application you intend to use.

## Native model boundaries

This table describes representable data in `src/types.ts`; it is not a claim that every corresponding PowerPoint construct imports faithfully. The implementation and its automated fixtures determine the supported interchange subset.

| Area            | Version-1 native model                                                                                                                                                      | Limit                                                                                                 |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| Slides          | Ordered slides, custom dimensions, background, name, notes, hidden flag                                                                                                     | No sections, custom shows, or master hierarchy                                                        |
| Text            | Base style plus optional rich runs: font, size, color, bold, italic, underline, safe text hyperlinks; independent text opacity                                              | No superscript/subscript, strike-through, per-run opacity, equations, or embedded fonts               |
| Paragraphs      | Left/center/right alignment, bullets, decimal numbers, nesting, starts/continuation, relative or fixed-point line spacing, before/after spacing, blanks and soft breaks     | No exact bullet indents, custom tab stops, justified/vertical text, or full typography                |
| Text frames     | Signed insets, wrapping, independent horizontal/vertical clip or overflow, top/middle/bottom anchor, first/last paragraph spacing policy                                    | No columns, ellipsis, or exact whole-line clipping                                                    |
| Text decoration | Rectangle, rounded rectangle, ellipse, triangle; independent solid fill and border opacity, border width, 11 dash patterns, caps, joins, miter limit, rounded-corner radius | No gradient/pattern/picture paints, custom paths, compound borders, or arbitrary geometry adjustments |
| Text fitting    | No fitting, shrink text with saved font scale and line-spacing reduction, resize shape; live fitting after relevant edits                                                   | Browser measurements and application reflow can differ; no complete PowerPoint layout engine          |
| Shapes          | Rectangle, rounded rectangle, ellipse, triangle, line, arrow                                                                                                                | No freeform paths, SmartArt, 3D, gradients, or complex DrawingML geometry                             |
| Geometry        | Position, size, rotation, opacity, lock                                                                                                                                     | No persistent group hierarchy or connector attachment model                                           |
| Images          | Source, alternative text, contain/cover fit                                                                                                                                 | No full image-editing/effects model                                                                   |
| Tables          | Text grid, header flag, common color/fill/font size                                                                                                                         | No merged cells, per-cell rich formatting, or formula model                                           |
| Charts          | Bar, line, pie; one label/value series                                                                                                                                      | No linked Excel workbook, multi-series, combination, or advanced charts                               |
| Themes          | Palette and font                                                                                                                                                            | Not an OOXML theme/master/layout implementation                                                       |
| Presenting      | Slide transition setting and basic element animation setting                                                                                                                | Browser playback does not imply PPTX timing equivalence                                               |

Rich paragraphs are optional in native schema version 1, so earlier plain-text documents remain valid. Their plain-text projection must exactly match the text box's `text` value. Explicit false run styles override the base style; omitted run styles inherit it. Alpha.1 readers can discard rich fields when re-saving, so use alpha.2 or later for rich native backups.

`textFrame` is also optional in schema version 1. Its absence preserves the earlier zero-inset, square-wrapped, clipped-on-both-axes behavior. An explicit frame stores all four insets and both overflow modes. Use alpha.3 or later to retain these fields when re-saving a native backup.

Alpha.4 adds optional `autoFit` and paragraph `lineSpacingPoints` fields to schema version 1. Absent fitting means no fitting. Shrink mode stores scale and reduction separately from the original run sizes; loading, rendering, and exporting retain those saved factors. Relevant text or geometry edits update the persisted fitting result. Fixed-point line spacing is mutually exclusive with relative `lineSpacing`. Use alpha.4 or later to retain these fields in native backups.

Alpha.5 adds optional `decoration`, `textOpacity`, and `textFrame.paragraphSpacingAtEdges` fields. A missing decoration means an unpainted rectangular text box; missing text opacity means 1. A missing edge-spacing flag preserves legacy behavior by including the first paragraph's before-spacing and the last paragraph's after-spacing. PPTX's omitted flag instead imports as false. Use alpha.5 or later to retain these extensions when re-saving native backups.

Whole-object `opacity` remains separate from glyph and paint opacity. PPTX export multiplies it into the text, fill, and border alpha independently. Import materializes those effective component values with whole-object opacity set to 1; the original split between whole-object and component opacity cannot be recovered from those baked values. A null paint means no fill or border, while a paint with opacity zero remains an explicit transparent paint.

## Interchange status and verification

The importer and exporter have regression tests in `src/pptx.test.ts`. Passing those tests establishes only the exercised cases, not arbitrary PowerPoint compatibility. The following describes the implementation; it is not an external-application visual certification.

Original PowerPoint-authored input decks supplement synthetic test packages and generated round trips. Their [provenance](FIXTURES.md) is recorded separately; this small fixture set cannot establish broad format fidelity.

| Feature                                 | PPTX import                                                                                                                                                                   | PPTX export                                                                                                                  |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Slide order and dimensions              | Reads the presentation's ordered relationship IDs and slide size                                                                                                              | Writes the native deck's order and dimensions                                                                                |
| Solid backgrounds, notes, hidden slides | Supported subset, including notes-body text                                                                                                                                   | Written to standard parts and properties                                                                                     |
| Text and formatting                     | Supported mixed font/size/color/bold/italic/underline runs; limited placeholder/theme inheritance; blank paragraphs and soft breaks                                           | Native editable rich text boxes and supported character styles, blanks, and breaks                                           |
| Paragraphs and lists                    | Alignment, native bullets/decimal numbers, levels, starts/continuation, relative or fixed-point line spacing, before/after spacing                                            | Native paragraphs and lists; exact point spacing retained; indents normalized; some adjacent numbering restarts can continue |
| Text frames and anchors                 | Per-attribute slide/layout/master cascade for insets, wrap, overflow, anchor, and first/last paragraph spacing; explicit zero/false overrides retained                        | Explicit DrawingML body properties, including the resolved edge-spacing policy; no master hierarchy                          |
| Attached text decoration                | Supported closed text shapes become one editable text object; supported paints, theme matrix references, partial border inheritance, opacity, radius, dashes, caps, and joins | One native shape with editable rich text, explicit preset geometry, and independent effective paint/text alpha               |
| Text fitting                            | Nearest slide/layout/master fit choice; no/normal/shape fit; saved normal scale and reduction in numeric or percentage form                                                   | One native fit choice, saved shrink factors or resize geometry, and unchanged base run sizes                                 |
| Text hyperlinks                         | Validated external HTTP/HTTPS/mailto links retained; internal, hover, shape, and action links omitted                                                                         | External text hyperlink relationships; PowerPoint's theme link colors can change appearance                                  |
| Geometry and stacking                   | Preserves supported object order and basic transforms; groups flattened; rotated/flipped groups approximate                                                                   | Native positioned objects; table/chart rotation and opacity omitted with warnings                                            |
| Shapes                                  | Six supported shapes; other presets approximate rectangles; block arrows become line arrows                                                                                   | Native basic shapes; horizontal line and line-arrow geometry                                                                 |
| Raster pictures                         | Embedded PNG/JPEG/GIF/WebP; linked and unsupported vector images skipped; crop approximated                                                                                   | Embedded images with contain/cover sizing; receiving-application support varies by image format                              |
| Tables                                  | Rectangular text grids; merged cells and styling simplified; equalized row/column sizes                                                                                       | Native editable tables using the application's simple header/body styling                                                    |
| Charts                                  | First cached series of bar/line/pie; other types omitted; chart styling simplified                                                                                            | Native editable single-series charts; appearance differs from the browser chart renderer                                     |
| Themes and masters                      | Some theme colors, fonts, and placeholder bounds; decorative master/layout objects omitted                                                                                    | Basic theme fonts and explicit element styling; no editable master hierarchy                                                 |
| Slide transitions                       | Fade and push subset; direction/duration can differ                                                                                                                           | Fade or left push; not exact browser timing                                                                                  |
| Element animation                       | Timing tree not imported                                                                                                                                                      | Browser entrance animations not written; warning shown                                                                       |
| Comments, audio/video, SmartArt, 3D     | Unsupported or omitted, with warnings for detected constructs                                                                                                                 | Not represented in the native model                                                                                          |

Complex theme inheritance, groups, animation timelines, media, custom geometry, and unsupported Microsoft extensions need particular attention. Linked images and external data are not fetched. Warnings cannot be assumed to enumerate every visual difference. Fonts and text layout can differ even when text and coordinates are retained.

One original five-slide exported sample was opened, rendered, visually inspected, saved again in Microsoft PowerPoint 16.0, and imported back with its slide/object counts, notes, and text preserved. A separate original two-slide rich-text fixture passed PowerPoint open/render/save and semantic re-import checks for every character's supported formatting and link, paragraph/list/spacing data, breaks, and notes. A focused browser test confirmed selected-word formatting and persistence after reload. Exact files, procedures, and remaining checks are in the [testing record](TESTING.md).

The autofit evidence includes a seven-slide PowerPoint-authored baseline and a separate XML-derived saved-scale probe. Windowless COM enabled normal fitting in the original but did not calculate saved shrink factors; that original is not evidence of automatically computed shrinking. The probe inserts documented factors without changing the nominal run sizes. PowerPoint opened, rendered, and saved both OpenDeck exports, and semantic re-import checks passed for modes/factors, rich text, fixed/relative spacing, frames, geometry, anchors, notes, and counts. [Fixture provenance](FIXTURES.md) distinguishes the original and derived inputs.

Alpha.5 adds an original nine-slide PowerPoint decoration fixture and a separately identified XML-derived probe. Both OpenDeck exports passed native open/render/save and semantic re-import checks for attached paints, alpha, caps, joins, miter limits, corner radius, paragraph edge policy, rich text, frames, geometry, notes, and counts. Native text bounds also confirmed the supported preset text regions in exported rounded rectangles, ellipses, and triangles. The [testing record](TESTING.md) and [fixture provenance](FIXTURES.md) describe the exact evidence and its limits.

These checks do not establish pixel-identical rendering or a completed broad visual acceptance suite. No Keynote, Google Slides, or LibreOffice visual acceptance is recorded. Fullscreen and print-layout acceptance remain separate checks.

## Rich-text approximations

- Four signed text-box insets are retained. Omitted PPTX insets use DrawingML defaults (9.6 px left/right and 4.8 px top/bottom), while legacy native documents use zero. Missing PPTX overflow properties allow overflow; legacy native documents clip. Exact bullet margins and hanging indents are normalized from list level.
- Browser clipping is applied at the outer shape bounds independently on each axis. PowerPoint can additionally omit whole lines that cross the inset content bottom. A native probe exposed this difference; vertical-clip import/export reports warn about partial or additional browser lines. Font metrics and wrapping are not pixel-identical across engines.
- No fitting, shrink text, and resize shape modes are represented. The nearest explicit fit choice overrides inherited choices, including local `noAutofit`. Shrink factors scale displayed glyphs without rewriting base font sizes. Line-spacing reduction subtracts from relative spacing; fixed-point spacing, absolute before/after spacing, and normalized list indents remain unscaled. Export retains the saved mode and factors. Browser fitting and PowerPoint reflow can still produce different results.
- Relative line spacing does not imply equal line metrics across engines. A native probe measured a 28.8 pt line advance for 24 pt Arial at 100% spacing, or 1.2 times the font size. OpenDeck applies the stored multiplier through CSS line-height; it does not apply a universal 1.2 correction. Other fonts, glyphs, substitutions, and mixed runs can differ, so text bounds and automatic fitting are not pixel-equivalent.
- First-paragraph before-spacing and last-paragraph after-spacing follow `paragraphSpacingAtEdges`, imported/exported as `spcFirstLastPara`. False suppresses only those outer margins; interior paragraph spacing remains intact. Omitted PPTX values default to false, while legacy native documents default to true. The flag inherits independently from slide to layout to master, so an explicit local false overrides inherited true.
- Columns, vertical text, distributed/justified anchors, and ellipsis overflow are simplified with warnings.
- Supported rectangle, rounded-rectangle, ellipse, and default-triangle containers remain single text objects with attached paint. Their intrinsic text regions follow the DrawingML preset formulas, with body insets applied inside that region. Rendering and live fitting share these calculations, including region changes as a shape resizes. Custom triangle adjustments, other presets, and arbitrary paths remain approximate; unsupported containers can remain separate shape and text objects.
- Solid fills and borders, scheme colors with supported transforms, and theme `fillRef`/`lnRef` matrix references are materialized. Supported properties resolve through slide/layout/master inheritance independently; explicit no-fill and local line settings override inherited values. This is a supported subset, not a complete theme engine. Decorative master/layout objects and an editable master hierarchy remain unsupported. [Microsoft's property-resolution notes](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/c0c046ec-a61d-405d-88fe-74d8487a37d7) describe the underlying inheritance rules.
- Borders preserve 11 preset dash patterns, flat/round/square caps, round/bevel/miter joins, and miter limits. Missing caps use Office's flat default; missing joins use round, and an unspecified miter limit uses 8. SVG dash rasterization can differ from Office. A painted zero-width border is retained as a hairline and displayed at an approximate 1 CSS px; device resolution and zoom can change its appearance. Limits below 1 are retained, but SVG rendering uses a minimum of 1 with a warning. [Office outline behavior](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/5564035f-88ff-4ab8-bbfb-d2998a83324d) defines native hairlines and cap defaults.
- Gradient, pattern, picture, and group paints are omitted with warnings. Custom dashes, compound borders, non-centered border alignment, attached border arrowheads, unsupported color transforms, and custom geometry adjustments are simplified or omitted. Filled shapes can therefore differ even when their text remains editable.
- PowerPoint can apply its theme hyperlink colors even when an explicit run color is stored. The semantic color/link data can therefore match while visible text differs.
- Fixed-point line spacing is retained as points, including zero, and is not changed by shrink scaling or reduction. Percentage paragraph spacing before/after becomes points based on the first run's font size.
- Native decimal list starts and continuation are represented, but PowerPoint may continue adjacent numbering sequences that restart at the same base. Separate those sequences with an unnumbered paragraph when a restart must survive export.
- Non-decimal numbering becomes decimal numbers with periods. Picture and font-specific bullets become standard bullets; justified/distributed alignment becomes left aligned.
- Custom tab stops, vertical text, superscript/subscript, strike-through, capitalization effects, and text highlighting are not retained. Dynamic fields become their current editable text; mixed per-run opacity becomes the first effective glyph opacity with a warning, independently of fill and border opacity.

The rich text editor restricts pasted content to its supported schema. It accepts only validated absolute HTTP, HTTPS, and mailto hyperlinks and does not open them during editing. Safe link support is not support for PowerPoint interactive actions or embedded programs.

## Input limits

The PPTX importer limits compressed input to 50 MiB, declared or streamed expanded data to 100 MiB, individual extracted parts to 20 MiB, and XML parts to 5 MiB. It accepts 1–300 slides and rejects unsupported ZIP64/encrypted packages, unsafe archive paths, malformed XML, and DTD/entity declarations. A valid archive can still exceed supported feature or native-model limits.

Native documents are validated field by field. The current model allows 1–500 slides, at most 2,000 objects per slide and 20,000 total, 100 table rows and 50 columns, and 1,000 chart points. PPTX table import is narrower at 40 columns. These are input bounds, not promises of interactive performance at their maximum values.

Each rich text box allows at most 100,000 projected characters, 5,000 paragraphs, and 10,000 runs. Font sizes are 1–1,000 points; relative line spacing is 0.5–10 or fixed line spacing is 0–1,000 points; paragraph before/after spacing is 0–1,000 points; list levels are 0–8 and explicit numbering starts are 1–32,767. A legacy plain-text box can exceed the rich paragraph limit; the rich editor reports that capacity error without modifying the original.

Saved shrink font scale is a ratio from 0.01 to 1, and line-spacing reduction is a ratio from 0 to 132, following the DrawingML value ranges. The browser bounds the resulting relative line-height at zero. Live fitting uses the document's supported geometry limits and preserves saved results when a valid layout measurement is unavailable.

Text geometry is written directly in EMUs so very small boxes and large coordinates survive the export library's unit inference. Stored full-turn rotations remain nonzero, preserving their resize-anchor meaning. Native angles beyond DrawingML's signed 32-bit angle range are exported as equivalent angles with a warning. Very large non-text geometry still follows the export library's unit handling; the export report flags affected objects. This remains an interchange gap for extreme-size shapes, images, tables, and charts.

Text-frame insets are finite numbers from −10,000 to 10,000 CSS pixels. If margins consume the entire content width or height, that dimension is clamped to zero and the inspector shows a warning; the shape itself is not resized.

Decoration border widths are 0–100 CSS pixels; rounded-corner radius is a ratio from 0 to 0.5 of the shorter dimension. Text, fill, and border opacity are each 0–1. Miter limits are ratios from 0 to 21,474.83647 in the native model; this is an application limit, not a claim that all OOXML percentage forms have that bound. Imported values outside supported decoration ranges are limited with warnings.

| Format or capability                             | Status                                                           |
| ------------------------------------------------ | ---------------------------------------------------------------- |
| Native OpenDeck JSON                             | Versioned application document format; preferred OpenDeck backup |
| `.pptx`                                          | Partial import/export; inspect results and warnings              |
| `.ppt` binary                                    | Unsupported                                                      |
| `.odp`                                           | Unsupported                                                      |
| Password-protected/encrypted presentations       | Unsupported                                                      |
| VBA, OLE programs, add-ins                       | Not executed or implemented                                      |
| SmartArt, Morph, 3D, complete animation fidelity | Unsupported                                                      |
| Real-time coauthoring and cloud version history  | Not implemented                                                  |
| Installed/offline PWA                            | Not implemented; self-hosted local serving is available          |

## How to report an incompatibility

Provide a synthetic, redistributable deck; the authoring application/version; import/export steps; and the expected and actual result. If possible, isolate the failure to one slide and one object. Distinguish missing content, lost editability, appearance differences, and presentation behavior. Follow [CONTRIBUTING.md](../CONTRIBUTING.md) and omit confidential data.

## Specification sources

OpenDeck's interoperability work uses public specifications and independently created tests:

- [ECMA-376](https://ecma-international.org/publications-and-standards/standards/ecma-376/) defines the OOXML vocabularies and packaging conventions.
- [Microsoft PresentationML structure](https://learn.microsoft.com/en-us/office/open-xml/presentation/structure-of-a-presentationml-document) explains the related presentation, slide, layout, master, theme, and notes parts.
- [DrawingML body properties](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.bodyproperties?view=openxml-3.0.1) describes insets, wrapping, anchors, overflow and fitting; [CSS Overflow Level 3](https://www.w3.org/TR/css-overflow-3/) defines the browser clipping behavior used by the renderer.
- [ECMA-376 Part 1's supporting files](https://ecma-international.org/wp-content/uploads/ECMA-376-1_5th_edition_december_2016.zip) include `OfficeOpenXML-DrawingMLGeometries.zip/presetShapeDefinitions.xml`, which defines preset paths and intrinsic text rectangles.
- [DrawingML fill references](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.fillreference?view=openxml-3.0.1) distinguishes no-fill indices from foreground/background style matrices. [DrawingML tint](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.tint?view=openxml-3.0.1) defines color/white mixing; HSL luminance and saturation transforms remain distinct from RGB channel operations.
- [DrawingML normal autofit](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.normalautofit?view=openxml-3.0.1) describes saved font scaling and percentage line-spacing reduction; the [Open XML SDK schema](https://github.com/dotnet/Open-XML-SDK/blob/main/data/schemas/schemas_openxmlformats_org_drawingml_2006_main.json) records their numeric bounds.
- [MS-PPTX](https://learn.microsoft.com/openspecs/office_standards/ms-pptx/) documents PowerPoint extensions to OOXML.
- [MS-OE376](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376) documents Microsoft implementation differences.
- [MS-PPT](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-ppt) describes the separate legacy binary format.
- [PptxGenJS](https://github.com/gitbrent/PptxGenJS) supplies PPTX generation APIs; it is not a general-purpose PPTX importer.

The [roadmap](ROADMAP.md) describes how coverage and its evidence should expand.
